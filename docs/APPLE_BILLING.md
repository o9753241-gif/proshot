# Покупки Apple: как устроено и что настроить

## Чем отличается от Google Play

| | Google Play | App Store |
|---|---|---|
| Что присылает клиент | `purchase_token` — сам по себе ничего не значит | подписанная транзакция (JWS) |
| Как проверяется | запросом в Play Developer API через сервис-аккаунт | подпись проверяется локально по цепочке до корня Apple |
| Нужна ли сеть | да, на каждую покупку | нет; App Store Server API — только для перепроверки |
| Ключ покупки | `purchase_token` от клиента | `transactionId` из **проверенной** подписи |

Последняя строка важна: у Apple ключом повтора служит не то, что прислал клиент,
а то, что подтвердила подпись. Иначе повтор обходится подменой присланной строки.

## Что происходит при покупке

1. Клиент вызывает `product.purchase()` и передаёт `appAccountToken` — тот же UUID,
   что уходит в заголовке `X-Device-Id`.
2. Клиент шлёт JWS в `POST /api/v1/billing/verify` вместе с `sku` и `scenes_selected`.
3. Сервер проверяет подпись, сверяет `bundleId` и `productId`, вытаскивает `transactionId`.
4. Если такая транзакция уже начислена — возвращается существующая покупка.
5. Иначе создаётся `Purchase` с `provider="app_store"`, фото начисляются.
6. Клиент вызывает `transaction.finish()` — **только после** ответа сервера.

## Настройка на сервере

```
APPLE_BUNDLE_ID=ai.proshot.app
APPLE_APP_APPLE_ID=          # числовой ID из App Store Connect, после этапа 6
APPLE_ROOT_CA_DIR=/root/backend-ios/secrets/apple_roots
APPLE_KEY_ID=
APPLE_ISSUER_ID=
APPLE_PRIVATE_KEY_PATH=/root/backend-ios/secrets/AuthKey.p8
```

Корневые сертификаты — с https://www.apple.com/certificateauthority/, нужен как
минимум AppleRootCA-G3. Ключ `.p8` создаётся в App Store Connect → Users and Access
→ Integrations → In-App Purchase и **скачивается ровно один раз**.

Пока папки с сертификатами нет, покупки не проходят вовсе: отказ, а не пропуск.
Ветка «доверять клиенту» включается только флагом `ALLOW_UNVERIFIED_PURCHASES=true`
и предназначена для локальных прогонов.

## Песочница

Проверяющий из App Store тестирует покупку в песочнице. Её транзакции подписаны
для другой среды, поэтому сервер пробует обе: сначала боевую, затем песочницу, и
берёт ту, чья проверка прошла. Приём только боевой среды — типовая причина отказа
с формулировкой «покупка не начислила товар».

## Уведомления о возвратах

`POST /api/v1/billing/apple/notifications` — адрес указывается в App Store Connect
отдельно для боевой среды и песочницы. Сейчас обрабатывается `REFUND`: покупка
помечается `status="refunded"`.

**Остаток фото при возврате не обнуляется.** Что делать с уже начисленными
снимками — продуктовое решение, а не техническое, поэтому оставлено как есть.

## Проверка

```
cd server
PYTHONPATH=. ALLOW_UNVERIFIED_PURCHASES=true python tests/test_billing_flow.py
```

Прогон проверяет начисление, повтор транзакции, лимит сцен пакета, обязательность
полей, отказ по чужому провайдеру, отказ по неподтверждённой подписи уведомления
и то, что без сертификатов и без флага покупка не проходит.
